## 1. What (c) is

Up to now every hypothesis was written by hand: in (a), one harmonic source
against a harmonic source plus a whistle; in (b), one note against two, each
started at the true parameters. Each source had exactly one event, and the
source parameters (the Gaussian-process variances and lengthscales) were fixed
at the medians of Table A.2.

A scene grammar is the paper's full prior over scenes [paper App. A.1,
Eqn A.2]:

    p(S) = p(n) ∏ᵢ p(Eᵢ | Θᵢ, mᵢ) p(Θᵢ | Tᵢ) p(Tᵢ) p(mᵢ)

a number of sources n, each with a type T, source parameters Θ and a number of
events m, each event with its timing and trajectories. It does two jobs. It
defines which scenes are possible and how probable each is, which is what lets
hypotheses with different numbers of sources and events be compared. And it
gives the space that a search moves through when the hypotheses are no longer
written by hand.

What carries over unchanged: the FFT cochleagram with BASS's gain, the
Gaussian likelihood (SD settable since PR #24), the renderers, the f0 and
level trajectories, the variational evidence (PR #20), float64. The new parts
sit above them.

## 2. What the scene code has now, and what it lacks

| Part of the paper's model | Now | Missing |
|---|---|---|
| Number of sources p(n) | zero-truncated Poisson(1 per s × duration), scoring only (design D8 (A), `priors.log_prior_structure`) | sampling with the same distribution |
| Source type p(T) | uniform over 3 types | the noise type (renderer and OU spectrum prior) |
| Events per source p(m) | Geometric(0.5), always m = 1 | m > 1: rests, durations, events sharing one source |
| Event timing | first onset uniform; log duration Student-t, the normal-gamma integrated out [paper Table A.1] | rests between events; durations of several events sharing (μ, λ) |
| Trajectory kernels | SE plus β² everywhere (correct for one event) | the non-stationary term per event [paper Eqn A.17] |
| Source parameters Θ | GP σ and ℓ fixed at Table A.2 medians | inferred, as the paper does |
| Hypotheses | written by hand | generated by a search |

## 3. Decisions

### C1. Scope of the milestone

**Options.**

- **(A) Grammar only.** Complete the generative model (C2–C6) and test it by
  enumerative inference on stimuli that need several events per source, as
  the paper did for streaming [paper App. C.10–C.11]. Hypotheses stay
  hand-written.
- **(B) Grammar, then a search with hand-built proposals.** (A), followed by a
  search that builds hypotheses from the sound (C9), tested by whether it
  finds the same winner as enumerative inference.
- **(C) Grammar, search and a learned proposal network**, as BASS's
  sequential inference [paper App. B.2.1].

**Recommendation: (B), in that order.** (A) is the part that changes what the
model can say, and it can be checked against the paper's streaming results
with the method we already trust. Search is what makes the grammar useful on
sounds nobody has labelled, so it belongs in the same milestone, but only once
(A) is tested. (C) is left out: the paper calls inference the central
challenge and says the proposal network still failed when it proposed the
wrong sound type [paper §4.2.2]; training it would need 100,000 sampled scenes
[paper App. B.2.1], which is out of proportion to our compute (design D6).
The search in (B) takes its candidate events through one interface, so a
learned proposer could replace the hand-built one later.

### C2. Several events per source

**What the paper specifies** [paper App. A.2, Eqns A.5–A.12]. A source emits
m events in order. The first onset is uniform over the scene. Each later
event starts after a rest; rests and durations are log-normal, with their own
(μ, λ) pairs per source, each pair drawn from the same normal-gamma prior
(μ0 −1, λ0 0.5, α0 2.5, β0 1) [paper Table A.1]. Events of one source cannot
overlap, by construction. The trajectories of all events of one source are one
Gaussian process across the scene, with the non-stationary term adding
covariance within each event [paper Eqns A.13–A.17].

**Options for the latents.**

- **(A) As the paper writes them:** first onset, then a log rest and a log
  duration per event.
- **(B) Onset and log duration per event**, with order and non-overlap
  enforced by the prior (zero density otherwise).

**Recommendation: (A).** It is the paper's parametrization, non-overlap
holds by construction (no zero-density walls for the optimizer to hit), and
it reduces to what the code does now when m = 1.

**One consequence worth knowing.** With p = 0.5, p(m) = 0.5^m, so a scene's
event-count prior is 0.5 to the power of its total number of events, however
they are divided among sources. One stream of 12 tones and two streams of 8
and 4 get the same event-count term; only p(n) and the rest of the prior
differ.

### C3. Source parameters (σ, ℓ of each GP; μ, λ of rests and durations)

**Options.**

- **(A) Keep σ and ℓ fixed at the Table A.2 medians**, as in (a) and (b).
- **(B) Infer σ and ℓ as latents**, under the paper's priors: inverse
  softplus normal, truncated to the Table A.2 bounds [paper App. A.3].
- **(C) Infer (μ, λ) of rests and durations as latents.**
- **(D) Integrate (μ, λ) out in closed form.** The normal-gamma is conjugate
  to the log-normal, so the log rests (or log durations) of one source have a
  closed-form joint density, a multivariate Student-t. The code already does
  this for one event.

**Recommendation: (B) and (D)**, with (A) kept as an option so (a) and (b)
reproduce exactly.

- (B), because with several events these parameters carry the result. Whether
  A and B tones belong to one source depends on how likely a source is to jump
  between them, which is the f0 GP's σ and ℓ. With them fixed (ℓ = 2.5 s), the
  model cannot trade a shorter lengthscale for the jumps, and I expect the
  one-stream hypothesis to be penalized at every Δt, so the dependence on
  tempo would not appear [estimate: reasoning from the kernel, not run]. It is
  also the untried item from (a): the 100 Hz first-harmonic threshold (26.6%
  against the paper's ~45%) has never been run with σ and ℓ inferred.
- The (b) octave is a second test case for (B). At SD 5 and 10 dB it stays
  one source, and one source follows about half of the upper note's late
  6 dB step through its level trajectory [measured:
  results/two_notes/sigma5/README.md]. A shorter level-GP ℓ would make that
  cheaper, so inferring ℓ should push the octave further toward one source.
  That is the (b) thread's reading and has not been run.
- (D), because it is exact, removes two latents per pair, and is what the
  current code already does for m = 1. The paper infers them by variational
  inference instead, which (D) does exactly.
- Reading Table A.2's "Dist. params." as (mean, SD) of the normal is my
  reading. It fits the medians (softplus(5.6) = 5.6 against Q2 5.9 for the f0
  σ; softplus(−1.7) = 0.17 against Q2 0.18 for the harmonic level ℓ). A
  `tools/` script will check all three quartiles by sampling before anything
  rests on it.

### C4. Event membership in the non-stationary kernel

The non-stationary term adds β² between two time points only when both fall
inside the same event [paper Eqn A.17]. As an onset is optimized, grid points
move in and out of an event, so with a hard rule the prior jumps whenever an
onset crosses a 10 ms grid point. BASS uses a hard step mask built from each
event's timing (`model/feature.py:136-141`) [code].

**Options.**

- **(A) Hard membership**, as written in the paper and in BASS.
- **(B) Soft membership:** weight each grid point by the event's ramp
  envelope w(t), so the term is β² Σⱼ wⱼ(t₁) wⱼ(t₂). Smooth in onset and
  duration; equal to (A) at grid points well inside or outside an event.

**Recommendation: (B)**, and check it against (A) at the fitted mode of each
test stimulus (the log prior should differ only by the few grid points under
the ramps). Gradient-based fits of onsets were already fragile in (a) and
(b); a prior that is discontinuous in onset would make them worse. This is a
departure from the paper's text, so it is labelled as such in the code.

### C5. The noise type

**Options.** (A) Add it now: frozen pink noise, the OU spectrum prior on a
0.3 ERB grid, the cosine filterbank [paper App. A.2, A.5]. (B) Later.

**Recommendation: (B).** None of the stimuli proposed for (c) contains noise,
and the type prior already gives each of the three types 1/3, so adding noise
later changes no log odds computed before. It becomes a separate PR, needed
when (c) or a later milestone takes up the continuity illusion or everyday
sounds.

### C6. Counting the sources of a hypothesis

A fit finds one mode with labelled sources (source 0, source 1, ...). Any
permutation of the labels gives another mode with the same density, and the
hypothesis "these sounds, as these sources" includes all of them. With
distinct continuous values, n sources have n! such labellings, so the
hypothesis's prior mass is n! times what the fit measures. This n! cancels
the 1/n! of the Poisson, as in a Poisson point process.

Now: `log_prior_structure` multiplies by n! / ∏ₜ cₜ!, the number of distinct
type orders (cₜ is the count of type t). That equals n! only when no two
sources share a type. BASS multiplies by neither (`model/scene.py:181-189`)
[code].

**Options.** (A) n!, as argued above. (B) Keep the number of type orders.
(C) Neither, as BASS.

**Recommendation: (A).** The difference is log ∏ₜ cₜ!. For (a) it is zero
(one harmonic and at most one whistle). For (b) it raises two notes over one
by log 2 = 0.69, and the harmonic-plus-whistles hypothesis by log 8! = 10.6
at the tritones (8 whistles) and log 4! = 3.2 at the just fifth (4 whistles)
[computed from the formula, not re-run]. None changes a conclusion of (b).
Across seeds 0 to 4, the evidence estimates vary by an SD of 2 to 5
[measured: results/two_notes/seeds/README.md], so the 0.69 and 3.2 shifts
are below that noise. The just fifth's whistles against one source is a tie
across seeds, and two notes beat both by about 50. For (c) it matters more: one stream of
12 whistle events is one source and two streams are two (log 2 = 0.69 in
favour of two streams), and a search will compare scenes of several same-type
sources, where log c! grows quickly (log 4! = 3.2). The fix is one
line plus a test on a toy model where the evidence is exact. Asking Maddie
whether BASS's omission was intended goes on the design v1 §6 list.

### C7. Where the grammar lives in the code

Cho asked (2026-10-11) to keep the option of plugging into Pyro later.

**Options.**

- **(A) Extend `scene.py` only.** Each source gets a tuple of events, and
  `Scene` gains `sample(generator)`. `log_prior` and `structure_log_prior`
  cover the new terms. Priors stay as functions that return log densities.
- **(B) Pyro as the core.** A scene becomes a Pyro model, and Pyro's traces
  do the scoring and sampling. Pyro's SVI and guides replace our fit and
  evidence code.
- **(C) Pyro-ready, Pyro optional.** As (A), but every prior term is a
  `torch.distributions` object at a named site, using the names we already
  have (`"h0.f0_mean"`). `Scene.model()` would issue `pyro.sample` at those
  sites. Pyro would be imported only there, as an optional install extra like
  sonore (design D2). Our fit and evidence code keeps calling `log_prob` on
  the same distribution objects. A test checks that Pyro's trace log density
  equals `Scene.log_prior`.

**Pros and cons.**

| | (A) scene.py only | (B) Pyro core | (C) Pyro-ready |
| --- | --- | --- | --- |
| (a) and (b) reproduce exactly | yes | no; fit and evidence rewritten, so every check must be redone | yes |
| New dependency | none | Pyro required | Pyro optional |
| Pyro's inference available later (autoguides, HMC/NUTS, amortized guides) | needs a retrofit of every prior | now | through `Scene.model()`, no retrofit |
| Our variational evidence (Laplace-whitened coordinates, PR #20) | kept | needs a custom Pyro guide | kept |
| Sampling and scoring from one definition (D8) | two code paths, tied together by a test | one definition | one definition per prior |
| Work in (c) | least | most | modest: write each prior as a distribution |

Notes on (C).

- The zero-truncated Poisson for n has no stock distribution class, so it
  needs a small custom one. Everything else is stock: uniform, Student-t,
  geometric, categorical, and multivariate normal for the GPs.
- C6's n! is a fact about the hypothesis, not about any one sample site. A
  Pyro trace of one labelled scene would therefore differ from
  `structure_log_prior` by exactly log n!. The test will check for that
  difference, and the code will say why.
- With D5, (C) also makes it cheap to measure HMC against our variational
  fit on one illusion.
- Checked here (2026-10-11): pyro-ppl 1.9.2 installs from PyPI with Python
  3.13, and a model with a loop over sources traces and scores. I have not
  checked Python 3.14, which is what Cho's PC and laptop run.

**Recommendation: (C).** It keeps what (a) and (b) verified and adds no
required dependency, and Pyro can be plugged in later without rewriting the
priors. (B) would be worth it only if we wanted Pyro's inference to replace
ours now. Nothing in (a) or (b) points that way: the bottleneck was rugged
likelihoods, not missing inference machinery. Sampling (`Scene.sample`, or
Pyro's trace) uses the same distributions as scoring (D8). A test checks
that the two agree, comparing structure frequencies from many samples with
`structure_log_prior`.

### C8. Test stimuli for the grammar

**Options.**

- **(A) ABA bistability** [paper App. C.10]: 30 stimuli (5 Δf × 6 Δt), each
  12 whistle tones in 3.1 s; one stream (one source, 12 events) against two
  (8 A events, 4 B events). Our generator exists (`stimuli/bistability.py`).
- **(B) Buildup of streaming** [paper App. C.11]: 12 stimuli, 1–6 ABA
  triplets at 500 Hz, 0.5–3 s, the same two hypotheses.
- **(C) Both.**

**Recommendation: (A) first, then (B) if (A) works.** (A) is a two-parameter
map with a clear expected pattern (two streams at large Δf and short Δt) and
is the classic test of exactly what C2–C4 add. (B) reuses everything and adds
the effect of sequence length, which is where the duration-scaled p(n) (D8)
and the per-event priors act. Start every hypothesis at the true tone
frequencies and timings, as the paper did [paper App. C.10] and as (a) and
(b) did. Evidence estimates in (b) varied by an SD of 2 to 5 across seeds
(results/two_notes/seeds/README.md), so any ABA margin under about 10 gets
seeds 0 to 4 (the `--seed` option, PR #28) before it is read as a preference.
Larger margins are first run with one seed.

### C9. Search over structures

The paper's sequential inference [paper App. B.2] builds hypotheses in rounds
over time: candidate events with onsets in the current window are added to an
existing source, start a new source, or are left out; each new hypothesis is
optimized briefly (250 steps), the best five are optimized fully, and the best
two seed the next round. Afterwards, cleanup moves remove a source or event,
change a type, or merge sources or events [paper App. B.2.4].

**Options for the candidate events.**

- **(A) A hand-built detector on the observed cochleagram:** onsets from rises
  in level across channels; for each onset, a whistle candidate at each
  spectral peak and a harmonic candidate at the f0 that best explains the
  peaks (subharmonic summation), plus that f0's octave above and below.
- **(B) Residual-driven proposals:** fit the current best scene, find where
  the observed cochleagram exceeds the rendered one most, and propose events
  there, as in (A) but on the residual.
- **(C) A learned proposer** (excluded by C1).

**Options for the search itself.**

- **(D) The paper's rounds and beam**, with its limits (≤ 5 new events per
  round, ≤ 4 sources, best two kept) [paper App. B.2.2–B.2.3], plus the
  cleanup moves.
- **(E) Stochastic search** (reversible-jump MCMC or SMC with birth, death,
  split and merge moves).

**Recommendation: (A) with (B) as a second pass, and (D).** (A) gives every
round its candidates without any fitting. (B) catches what (A) missed, such as
a quiet note under a louder one, using the model itself. The octave
alternatives are proposed explicitly because octave errors are local minima
gradient descent cannot leave [paper §4.2.2]. (D) is the paper's method and
needs tens, not thousands, of hypothesis fits. (E) would need many more
fits, each taking minutes on our hardware (§4), so it does not fit the budget.

### C10. Evidence during search

**Options.**

- **(A) As the paper:** a short variational fit for every hypothesis, rank by
  ELBO, then full variational fits for the best five.
- **(B) Screen by the MAP fit's log joint plus the Laplace estimate, then
  variational evidence for the best five.**

**Recommendation: (B).** A MAP fit is the first stage of our variational
evidence anyway, so screening costs nothing extra for the hypotheses that go
on. Laplace was unreliable in (b) for close calls (its estimate moved by up to about 15
between 300 and 3000 Adam steps [measured: results/two_notes/README.md]),
which is why only the screen uses it and the final ranking uses variational
evidence, as (b) chose. Keeping five rather than one absorbs that noise. Each
hypothesis is fitted from every starting point its candidates allow, and the
best kept, as in (b).

### C11. What counts as success

- **Grammar:** sampling and scoring agree (C7's test); the new code
  reproduces (a) and (b) exactly with σ and ℓ fixed and one event per source,
  apart from C6's log ∏ cₜ!.
- **ABA:** the log odds of two streams over one, across Δf × Δt, compared
  with the paper's model map [paper Fig. 8D, read by eye] and, with
  care, with listeners. Expected, to be checked rather than assumed: two
  streams more likely at larger Δf and shorter Δt.
- **Search:** on the (b) stimuli and the ABA stimuli, the search's best
  hypothesis has the same structure as the enumerative winner, without being
  given the stimulus. Report the number of hypotheses fitted and the time per
  stimulus.

No claim about perception beyond those comparisons.

## 4. Size (estimates)

- A two-note (b) hypothesis (0.5 s, two harmonic sources, 232 parameters)
  took 380–395 s on the cloud CPU for its whole evaluation: 300 Adam steps,
  the Laplace and importance-sampling estimates, and 2000 variational steps
  [measured: results/two_notes/variational/tritone.txt, `seconds` column].
- An ABA hypothesis is 3.1 s, about six times longer, with whistles (one
  component each) instead of harmonic sources (up to 12 components). Run time
  scales roughly with duration, so about 30–40 min per hypothesis on the cloud
  CPU [estimate: linear in duration from the (b) timing; whistles are cheaper
  to render, the GP over 311 grid points dearer]. 30 stimuli × 2 hypotheses is
  then about 30–40 h on one CPU, or a few runs in parallel on Cho's PC.
  To be measured on the first stimulus before the rest are run.
- Search on a (b) stimulus: tens of hypotheses screened, five taken to full
  variational fits [estimate from C9's limits], so roughly 1–3 h per stimulus
  on the cloud CPU. Also measured on the first stimulus.

## 5. Order of work

1. C6: count labellings as n!, with the toy-model test; note the shift in
   (b)'s log odds in the results README (PR).
2. C2 + C4: several events per source, rests and durations with (μ, λ)

   page and step log).
5. C9 + C10: the detector, the rounds, the cleanup moves; run on (b) and ABA
   (PR).

Each step is one PR; nothing past step 1 starts before Cho accepts this.
